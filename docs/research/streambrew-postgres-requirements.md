# StreamBrew readiness on current BoxDB

The current working tree supplies the core primitives needed by StreamBrew: **exact native decimals with rounded division, asynchronous TypeScript transactions, Go access, structured errors, safe writable-transaction defaults and enforced read-only transactions**. Same-client auth requests wait for their transaction; cross-connection auth writes now acquire the writer before invoking the callback. The Unicode text_like defect is also fixed locally. No additional mandatory BoxDB capability was identified when application/query rewrites are allowed. Full application parity still requires real auth/session, money-query, worker, deployment and recovery integration. [Decimal contract](https://github.com/lebedev-nikita/boxdb/blob/119e53600394201f0038d4537189e7e4fa5c3d43/docs/native-decimal.md#L19-L58), [current TS transaction contract](../../packages/typescript/README.md), [current Go contract](../../packages/go/README.md).

Sources checked on 2026-10-14: the original BoxDB assessment used [`119e53600394201f0038d4537189e7e4fa5c3d43`](https://github.com/lebedev-nikita/boxdb/tree/119e53600394201f0038d4537189e7e4fa5c3d43), with integration rebased and rechecked on [`e95f6c4987eed0222956e06d3ba9ef835a38ed0c`](https://github.com/lebedev-nikita/boxdb/tree/e95f6c4987eed0222956e06d3ba9ef835a38ed0c). StreamBrew was inspected at [`9a1d1f4c186871beb3a6528ec7283ca7f8ddedd2`](https://github.com/streambrew-app/streambrew/tree/9a1d1f4c186871beb3a6528ec7283ca7f8ddedd2). This is a capability assessment, not a completed migration. This branch fixes the text_like matcher and changes the TS/Go transaction helpers to immediate by default, with enforced read-only support and public regression tests. The earlier source links describe the original inspected commit; updated temporal/JSON contracts are linked below. No application schema or deployment was changed. Backward compatibility is not a requirement, so callers/schema declarations should adopt current APIs directly.

## Monetary parity requires the correct existing API

StreamBrew currently uses `round(amount * numerator / denominator,2)`. BoxDB's ordinary DECIMAL division deliberately rejects a nonterminating quotient **before** outer round can execute; PostgreSQL's numeric pipeline does not have that same restriction. Native exact arithmetic therefore does not make the current SQL unchanged-compatible. [StreamBrew conversion](https://github.com/streambrew-app/streambrew/blob/9a1d1f4c186871beb3a6528ec7283ca7f8ddedd2/apps/web/src/server/video-queue/postgres.ts#L479-L489), [division policy](https://github.com/lebedev-nikita/boxdb/blob/119e53600394201f0038d4537189e7e4fa5c3d43/docs/native-decimal.md#L26-L42).

Use the existing `decimal_div(amount * CAST(? AS DECIMAL), ?, 2, 'half_up')` for configured numerator/denominator conversion: exact multiplication, then one rounding of the rational quotient. half_up rounds ties away from zero, matching the intended money policy; do not substitute half_even by default. Bind text for exact rates, cast parameters where a native decimal expression requires it, and never introduce JS Number/REAL conversion. Column scale is validated without implicit rounding. [Rates](https://github.com/streambrew-app/streambrew/blob/9a1d1f4c186871beb3a6528ec7283ca7f8ddedd2/packages/src/currency.ts#L23-L31), [exact one-rounding implementation](https://github.com/lebedev-nikita/boxdb/blob/119e53600394201f0038d4537189e7e4fa5c3d43/src/decimal.rs#L70-L110), [parameter/precision contract](https://github.com/lebedev-nikita/boxdb/blob/119e53600394201f0038d4537189e7e4fa5c3d43/docs/native-decimal.md#L14-L17).

Priority affordability can avoid division entirely: compare `queue_amount * 60 >= min_price_per_minute * duration_seconds`. Positive duration makes this equivalent at the exact threshold; plain native DECIMAL ORDER BY now supplies numeric priority order. This is a query rewrite using existing functionality, not a remaining engine addition. [Current priority formula](https://github.com/streambrew-app/streambrew/blob/9a1d1f4c186871beb3a6528ec7283ca7f8ddedd2/db/schema.sql#L204-L211), [duration constraints](https://github.com/streambrew-app/streambrew/blob/9a1d1f4c186871beb3a6528ec7283ca7f8ddedd2/db/migrations/20260909000000_initial_schema.sql#L275-L286).

**Acceptance:** reverse-rate recurring fractions, positive/negative ties, values beyond JS-safe integer range, scale-18 donation values, DECIMAL(38,18)/(20,2) bounds, exact threshold equality and both sides, whole-currency-change rollback and one-rounding consistency across CLI/Rust/TS/Go.

## Shared auth requests and cross-connection writer contention are covered

Root requests queue behind the entire active TS transaction. Transaction work bypasses blocked roots; after commit or rollback, roots execute independently in submission order. A shared-client probe previously confirmed overlapping adapter transactions, findMany, getSession HTTP 200 and rollback isolation. The current defaults additionally address independent writers. [Root scheduling](../../packages/typescript/src/database.ts), [waiting tests](../../packages/typescript/test/api.test.ts).

Both TS db.begin() and Go Begin/BeginTx acquire the writer with BEGIN IMMEDIATE by default. The Better Auth adapter already calls client.begin(), so it receives the policy without a separate transactionMode option. A new public adapter regression holds another connection's writer transaction: the callback stays uninvoked while waiting, then runs exactly once and creates one user after release. The earlier default-deferred BOXDB_BUSY reproduction is therefore addressed through the SDK. Waiting uses the existing busy timeout/cancellation, not transparent repetition of the callback. [SDK implementation](../../packages/typescript/src/database.ts), [auth regression](../../packages/better-auth-adapter/test/integration.test.ts), [Go helpers](../../packages/go/boxdb.go).

Read-only work uses TS begin({readOnly:true}) or Go sql.TxOptions{ReadOnly:true}: deferred acquisition plus a native query_only guard. Tests confirm stable binary WAL snapshots alongside an independent writer, prohibition of writes through prepared/tagged queries and scripts, resistance to PRAGMA query_only=OFF, savepoint inheritance, cancellation/timeouts and writable reuse after cleanup. TS preserves a pre-existing query_only setting. Go's normal pool reset clears its managed restriction. Typed metadata is refreshed for reads while writer-validation installation is deferred until writes are permitted again; an INSTANT concurrency regression verifies both reading and later write validation. [TS regressions](../../packages/typescript/test/options.test.ts), [Go regressions](../../packages/go/boxdb_test.go), [shared core](../../src/lib.rs).

A reusable pool remains optional for parallel reads. SQLite still has one writer per database file. Read-only connections automatically start read-only TS transactions; explicit deferred/exclusive writable modes remain available in TS. Native SQL BEGIN retains SQLite's own semantics. None of these changes introduce an engine pool, row-lock engine or callback retry requirement.

## Transaction deadlines and caller scope

Transactions have a configurable five-second default lifetime starting after BEGIN succeeds. Savepoints inherit the outer deadline. Expiry interrupts SQL, cancels queued transaction work, rolls back and only then releases waiting root requests. A fresh probe confirmed that running and queued transaction statements fail with BOXDB_TRANSACTION_TIMEOUT while a waiting independent root write succeeds after rollback. This covers the required deadline primitives; longer import operations can set an appropriate timeout. A total request deadline including queue wait uses the existing AbortSignal separately. [Deadline contract](https://github.com/lebedev-nikita/boxdb/blob/119e53600394201f0038d4537189e7e4fa5c3d43/packages/typescript/README.md#L92-L129), [deadline tests](https://github.com/lebedev-nikita/boxdb/blob/119e53600394201f0038d4537189e7e4fa5c3d43/packages/typescript/test/options.test.ts#L7-L128).

Work intended to belong to a transaction must use its tx handle/adapter. Awaiting the root Database from inside its own transaction waits until the transaction ends, which can mean timeout/rollback followed by the root operation executing independently. This is documented caller behavior, not a demonstrated StreamBrew defect; the Better Auth callback correctly receives a transaction-scoped adapter. Automatic async-context routing or misuse guards would be optional ergonomics. [Caller contract](https://github.com/lebedev-nikita/boxdb/blob/119e53600394201f0038d4537189e7e4fa5c3d43/packages/typescript/README.md#L84-L111).

## Unicode text_like matching is fixed in the working tree

The matcher now first treats % as matching zero characters, and advances the text position only when backtracking must consume another character. The public SQL regression first failed with 0 for text_like('%донат%','ДОНАТ') and passed with 1 after the two-line C fix. Additional cases cover Latin/Cyrillic/Ё, multiple and internal %, single-code-point _, suffix backtracking, anchored failures, empty strings and NULL propagation. [Local matcher](../../vendor/sqlean/text/rstring.c), [SQL regression tests](../../tests/extensions.rs).

The two-argument function still has its existing wildcard contract; this fix does not add an escape parameter. For user-entered literal %/_ searches, use text_lower(coalesce(author,'')) LIKE text_lower(?) with a chosen ESCAPE character and correctly escaped patterns. PostgreSQL production locale was not inspected, so broader locale parity remains an integration question. [Unicode functions](https://github.com/lebedev-nikita/boxdb/blob/119e53600394201f0038d4537189e7e4fa5c3d43/docs/extensions.md#L39-L53).

## Worker invariants to prove with existing primitives

Use short immediate transactions or conditional UPDATE/RETURNING instead of writable CTEs/SKIP LOCKED. Across independent Go/TS processes verify unique valid-generation claims, expiry/reclaim, stale completion rejection, atomic donation/deduplication/enqueue, atomic video completion, per-user alert ordering and stale-player fencing. These are workload acceptance tests, not evidence a new queue/row-lock engine must be built. [Claim/fences](https://github.com/streambrew-app/streambrew/blob/9a1d1f4c186871beb3a6528ec7283ca7f8ddedd2/internal/videoingest/store.go#L50-L158), [alert-order rationale](https://github.com/streambrew-app/streambrew/blob/9a1d1f4c186871beb3a6528ec7283ca7f8ddedd2/internal/donationalert/store_queue.go#L83-L92).

The BEFORE trigger fills an omitted NOT NULL queue ID and validates owner/priority references; an AFTER trigger is not interchangeable. Preserve this through explicit transactional writes/shared write rules or an appropriate schema design, covering every writer. Native DECIMAL now supplies exact priority arithmetic. PL/pgSQL/mutable NEW are not required additions. [Current trigger](https://github.com/streambrew-app/streambrew/blob/9a1d1f4c186871beb3a6528ec7283ca7f8ddedd2/db/schema.sql#L150-L219), [Go insert](https://github.com/streambrew-app/streambrew/blob/9a1d1f4c186871beb3a6528ec7283ca7f8ddedd2/internal/videoingest/store.go#L111-L126).

Same-host services can share one local **binary WAL** database via the existing Go/TS engine clients. A server/pure-Go remote client is conditional on different hosts or preserving a no-cgo deployment; readable YAML remains single-writer. Do not add PostgreSQL wire/catalog/search_path, old API facades, unchanged historical migrations, row locks, arbitrary writable CTEs, distributed queues or built-in replication solely to avoid accepted application rewrites. [Go pool/storage](https://github.com/lebedev-nikita/boxdb/blob/119e53600394201f0038d4537189e7e4fa5c3d43/packages/go/README.md#L71-L82), [format contract](https://github.com/lebedev-nikita/boxdb/blob/119e53600394201f0038d4537189e7e4fa5c3d43/README.md#L62-L67).
