# Built-in SQL extensions

Rust, TypeScript and the CLI register the same statically linked extensions on
every BoxDB connection, including snapshot import. No system extension packages
or runtime shared-library loading are needed. Registration is local to BoxDB's
connections and does not change other SQLite connections in the process.

| Capability | Implementation | Reference |
| --- | --- | --- |
| Full-text search | SQLite FTS5, including Unicode and trigram tokenizers | [FTS5](https://www.sqlite.org/fts5.html) |
| Spatial indexing | SQLite R*Tree | [R*Tree](https://www.sqlite.org/rtree.html) |
| Exact decimal arithmetic | SQLite `decimal.c` | [Decimal extension](https://www.sqlite.org/floatingpoint.html#decext) |
| Unicode text functions and collation | sqlean-text | [Text functions](https://github.com/nalgeon/sqlean/blob/0.28.4/docs/text.md) |
| Regular expressions | sqlean-regexp with PCRE2 | [Regexp functions](https://github.com/nalgeon/sqlean/blob/0.28.4/docs/regexp.md) |
| Vector search | sqlite-vec 0.1.9 | [sqlite-vec](https://github.com/asg017/sqlite-vec/tree/v0.1.9) |

## Exact decimals

`DECIMAL(p,s)` and `NUMERIC(p,s)` are identical SQL type names. Rust uses
`Type::Decimal` and `Value::Decimal`; serialized type/value tags are `Decimal`.
Bind decimal values as strings to avoid floating-point conversion before SQL
receives them.

```sql
CREATE TABLE prices(amount DECIMAL(12,2));
INSERT INTO prices VALUES('10.00'),('2.00'),('0.10'),('0.20');
SELECT decimal_sum(amount) FROM prices; -- text: 12.30
SELECT amount FROM prices ORDER BY amount COLLATE decimal;
SELECT decimal_add('0.1','0.2'), decimal_mul('0.1','0.2'); -- 0.3, 0.02
```

These functions return SQLite text. Ordinary `+`, `*`, `SUM`, comparison and
ordering retain SQLite's storage semantics; declaring DECIMAL does not replace
them. The extension provides no decimal division function. Division would need
an explicit precision and rounding policy.

## Text and regular expressions

```sql
SELECT text_lower('ПРИВЕТ'); -- привет
SELECT 'Ёж' = 'ёж' COLLATE text_nocase; -- 1
SELECT text_split('a/b/c','/',2); -- b
SELECT regexp_substr('order #123','\d+'); -- 123
SELECT regexp_replace('a1b2','\d','_'); -- a_b_
```

Use the explicit `text_nocase` collation for Unicode comparisons. SQLite's
`lower`, `upper`, `NOCASE`, `concat`, `concat_ws`, `ltrim`, `rtrim` and
`octet_length` keep their original behavior. sqlean's corresponding functions
remain available as `text_concat`, `text_join`, `text_ltrim`, `text_rtrim` and
`text_size`. These names do not redirect calls inside other sqlean functions.

## Full-text and vector search

```sql
CREATE VIRTUAL TABLE documents USING fts5(title,body);
INSERT INTO documents VALUES('SQLite guide','A small database');
SELECT title, bm25(documents), highlight(documents,0,'[',']')
FROM documents WHERE documents MATCH 'sqlite' ORDER BY bm25(documents);

CREATE VIRTUAL TABLE fragments USING fts5(body,tokenize='trigram');
INSERT INTO fragments VALUES('abcdefghij');
SELECT body FROM fragments WHERE fragments MATCH 'cdefg';

CREATE VIRTUAL TABLE embeddings USING vec0(embedding float[3]);
INSERT INTO embeddings(rowid,embedding) VALUES(1,'[1,0,0]'),(2,'[0,1,0]');
SELECT rowid,distance FROM embeddings
WHERE embedding MATCH '[0.9,0,0]' AND k=1;
```

Trigram search matches substrings; it does not automatically correct typos.
FTS5 indexes linked to ordinary tables need synchronization, usually with
application triggers as described in the FTS5 documentation.

`vec0` enforces vector element type and dimension. In an ordinary STRICT table,
use a BLOB column and `vec_f32(?)` to pack a JSON vector. BoxDB's `FLOAT4[]` is
a JSON array, not sqlite-vec's packed vector representation. Embeddings must be
generated by the application; sqlite-vec stores and searches them. The library
is pre-v1 and its version is pinned. Measure vector query latency for your data
and VPS before setting capacity limits.

## Storage and interoperability

Scalar extensions work with both binary SQLite and readable YAML. FTS5, R*Tree
and `vec0` virtual tables work in memory and binary databases, including binary
snapshot export and restore. Readable YAML does not support virtual tables;
attempting to create one rolls back the statement and leaves the file usable.

The file format remains ordinary SQLite. External SQLite connections need the
same modules, functions or collations when accessing schema objects that use
them. For example, an index on `text_lower(name)` requires that function, and a
table declaring `COLLATE text_nocase` requires that collation. Ordinary BoxDB
decimal storage does not require the decimal extension unless the schema itself
references its functions or collation.
